## 架构决策记录

### ① AuthService/AuthController 置于 library-security 而非 core

**计划原述**：`core/service/AuthService`、`core/controller/AuthController`。

**实际**：置于 `library-security/service`、`library-security/controller`。

**理由**：AuthService 强依赖 `JwtUtils`/`TokenService`（security 域）。模块依赖链为 `common ← core ← security`，若 AuthService 放 core 会形成 `core → security` 循环依赖（Maven 不允许）。security 已依赖 core，可访问 `SysUserMapper`/DTO/VO，因此认证全链路内聚到 security 模块，符合 SOLID-D（依赖抽象边界）与模块内聚原则。

### ② Filter 顺序：Jwt → RateLimit（后置）

RateLimitFilter 位于 JwtAuthenticationFilter 之后，从 SecurityContext 取 userId（已认证按用户聚合），无需"不验签解析 JWT"的 unsafe 方法。"过期 token 洪水绕过限流"威胁不现实（攻击者无密钥无法制造合法签名 token）。

### ③ Refresh Token = 自包含 JWT + Redis jti 校验

Refresh Token 是 JWT（含 sub/jti），有效性以 Redis `auth:refresh:{userId}`→jti 为准。`refresh_rotate.lua` 原子执行"GET+比对+SET"，保证并发下仅一个请求轮换成功，其余判定为重放并撤销整链。

### ④ 限流全端点 + 公开防爆破

认证端点按 userId 100/min；`/auth/login`、`/auth/register` 按 IP 20/min 防爆破；`/health`/swagger 不限流；匿名请求按 IP 100/min。

### ⑤ 初始管理员用纯 SQL V4

预生成 BCrypt(12) 哈希硬编码进 V4 SQL，比 Flyway Java Migration 更简单可靠。

## 架构原则遵循

| 原则 | 体现 |
|------|------|
| **KISS** | Access Token 无状态不落库；限流 Redis 异常降级放行；RBAC 静态权限派生（无独立权限表） |
| **YAGNI** | 不实现 Access 黑名单（2h 自然过期）；不实现独立权限关联表 |
| **DRY** | Redis 操作收敛到 `TokenService`/`RateLimitService` 单一接口；CORS 单一 `CorsConfigurationSource` |
| **SOLID-S** | JwtUtils（签发解析）/ TokenService（存储轮换）/ RateLimitService（限流）/ AuthService（业务编排）各司其职 |
| **SOLID-D** | Filter 依赖 Service 接口而非 Impl，便于单元测试 mock、未来补真实集成测试 |
| **SOLID-O** | `@RequireRole`/`@RequirePermission` 注解可扩展新角色/权限无需改切面 |

## 已知限制

1. **Access Token 不即时吊销**：logout 仅删 Refresh Token，Access 2h 内仍有效（无状态 JWT 标准取舍；需即时吊销再加 `auth:blacklist:{jti}`）。
2. **UserProfile.id 序列化为字符串**：阶段 0 `JacksonConfig` 全局 Long→String 使 `id` 输出 `"1"`，与 OpenAPI integer/int64 略有出入；前端 Long 类型可正常解析，不改 JacksonConfig 以免回归。
3. **Refresh 并发撤销语义**：同一 RT 两次并发刷新，仅一个成功，另一触发链撤销需重新登录（Lua 原子保证，语义正确）。
4. **注册仅能创建 STUDENT**：OpenAPI 无 role 字段；其他角色由管理员后台（阶段 9）或 V4 seed 创建。
5. **初始管理员弱密码**：V4 预置 admin/Admin@123456，生产首登须改密。
6. **Access Token 不可即时吊销**：冻结/禁用账号后，已签发 AT 在 2h 有效期内仍可用（无状态 JWT 取舍；阶段 9 可引入 token 版本号或 AT 黑名单 `auth:at:blacklist:{jti}`）。
7. **method 级 `@PreAuthorize` 异常处理待补**：当前 RBAC 用自定义 `@RequireRole`（抛 BizException→GlobalExceptionHandler），未用 Spring Security `@PreAuthorize`；待阶段 3+ 启用 `@PreAuthorize` 时需新增 `@RestControllerAdvice` 处理 `AccessDeniedException`，否则被全局兜底为 500。
8. **限流 XFF 信任链**：`RateLimitFilter` 的 clientIp 信任 `X-Forwarded-For`，生产须在受信反代（Nginx）后部署并启用 `server.forward-headers-strategy: native` + `trusted-proxies`（阶段 9 监控加固）。
