## 一、P0 — 阻塞/实效缺陷（3 项）

### P0-1 [core] OverdueBatchProcessor 竞态条件：单条 FineRecord 唯一约束冲突导致整批回滚

- **文件**: `library-core/src/main/java/com/library/core/schedule/OverdueBatchProcessor.java:45-70`
- **问题**: `processBatch()` 在 `REQUIRES_NEW` 事务中逐条处理超期记录。当用户还书操作与超期检查并发时，还书操作先创建了 `FineRecord(borrowId=X)`，超期检查随后尝试 `insert(FineRecord(borrowId=X))` → `DuplicateKeyException` → 整批事务回滚 → 本批全部记录的 OVERDUE 标记和罚款丢失
- **修复**: 将 `fineRecordMapper.insert()` 包裹在 try-catch 中，捕获 `DuplicateKeyException` 后跳过该条继续

```java
try {
    fineRecordMapper.insert(fineRecord);
} catch (DuplicateKeyException e) {
    log.warn("罚款记录已存在(可能已被还书操作创建)，跳过: borrowId={}", record.getId());
    continue;
}
```

### P0-2 [kg] GraphQueryServiceImpl.searchEntities() 缺少 PageRank 排序

- **文件**: `library-knowledge-graph/src/main/java/com/library/kg/service/impl/GraphQueryServiceImpl.java:66-98`
- **问题**: 接口 Javadoc 声明 `@return 按 PageRank 排序`，但 Cypher 查询 `MATCH (n:Book) ... RETURN n LIMIT 50` 无 `ORDER BY`。前端按 PageRank 可视化时数据行为不可预测
- **修复**: 在 RETURN 前追加 `ORDER BY coalesce(n.pagerank, 0.0) DESC`，在 `buildNodeFromValue()` 中读取 `pagerank` 属性

### P0-3 [acquisition] NegotiationRecord.suggestedPrice 与 DB 列名 suggested_offer 不匹配

- **文件**: `library-acquisition/src/main/java/com/library/acquisition/entity/NegotiationRecord.java:29`
- **问题**: 实体字段名 `suggestedPrice` → MyBatis-Plus 驼峰映射为 `suggested_price`，但 DB 实际列名为 `suggested_offer`（V1__init_schema.sql:220）。导致该字段**静默无法读写**——所有新建谈判记录的 `suggested_offer` 列始终为 NULL
- **修复**: 将字段改名为 `suggestedOffer`（匹配 `suggested_offer` 驼峰映射），同步修改 `NegotiationVO.java:45` 和 `AcquisitionController.java:87` 中的引用；或添加 `@TableField("suggested_offer")` 显式映射
