### 2.3 借阅 Service

| 文件 | 关键功能 |
|------|----------|
| `service/BorrowService.java` | 接口：borrow / returnBook / renew / getMyBorrows / getBorrowDetail / getOverdueRecords |
| `service/impl/BorrowServiceImpl.java` | **核心实现**：|

**borrow 校验链**（7 步）：
1. 用户状态 ACTIVE（否则 ACCOUNT_FROZEN）
2. 图书存在 + avail_copies > 0（否则 BOOK_STOCK_EMPTY）
3. 活跃借阅数 < maxBooks（否则 BORROW_LIMIT_EXCEEDED）
4. 未重复借阅（否则 ALREADY_BORROWED）
5. 无超期未还（否则 OVERDUE_UNRETURNED）
6. Redis 分布式锁 `lock:borrow:{bookId}`（SETNX TTL 5s）→ 防并发超卖
7. MyBatis-Plus 乐观锁 version 扣库存 → 若冲突抛 CONFLICT
8. 创建 BorrowRecord（borrow_date=today, due_date=today+30d）
9. 发布 BookBorrowedEvent

**returnBook**：校验状态 → 恢复库存 → 计算超期罚款（0.5元/天）→ 生成 FineRecord → 发布 BookReturnedEvent

**renew**：校验 renew_count<1、未超期、未被预约 → 延长 due_date 30 天

### 2.4 预约 Service

| 文件 | 关键功能 |
|------|----------|
| `service/ReservationService.java` | 接口：reserve / cancel / getMyReservations / getQueuePosition |

## 4. 架构决策记录

| 决策 | 理由 |
|------|------|
| Controller 放 library-security，Service 放 library-core | 遵循 AdminBookController 模式；SecurityUtils 在 security 模块，避免循环依赖 |
| Redis 分布式锁 + MyBatis-Plus 乐观锁双重防护 | SETNX 减少并发冲突，version 作最终兜底 |
| Redis ZSET 为主排队数据源 | 天然有序（score=时间戳），O(log N) 入队，O(1) 查排名 |
| 预约通知当前为日志输出 | 通知推送渠道（站内信/邮件/推送）由阶段 9 实施 |
| @Scheduled 定时任务 | 超期检测（每日 3:00 批量扫描）；@EnableScheduling 在 bootstrap SchedulingConfig 集中启用 |
