## 二、P1 — 6 项

### P1-1 [common→core/security] 分页参数缺上限校验（4 个旧 Controller）

- **文件**: `PageDTO.java` + `BorrowController` / `ReservationController` / `UserCenterController` / `AdminBorrowController`
- **问题**: 4 个旧 Controller 以 `@RequestParam int pageSize` 接收分页参数后 `new PageDTO(pageNum, pageSize)` 手动构造，Bean Validation 注解（`@Min`/`@Max`）未走 `@Valid` 绑定路径而**完全不触发**。攻击者可传 `?pageSize=999999`（单次拉海量记录致 DoS）或 `?pageNum=-1`（负 offset 触发 SQL 异常）。`AdminUserController`（阶段 9）与 `RecommendationController` 已正确防御，旧 Controller 未同步。
- **修复**: `PageDTO` 移除 `@AllArgsConstructor`，手写带参构造器对入参做防御性钳制（`pageNum ≥ 1`、`1 ≤ pageSize ≤ 100`）。一处修复，全局生效；`@Min`/`@Max` 注解保留以覆盖 `@Valid` 绑定路径，形成"构造器钳制 + 注解校验"双层防护。

### P1-2 [ai] EmbeddingServiceImpl.batchEmbed 批次间无失败隔离

- **文件**: `EmbeddingServiceImpl.java:80-85`
- **问题**: 分批循环内 `doEmbed(batch)` 抛出的异常（重试耗尽后）向上传播终止整个 `batchEmbed`，导致后续批次未执行且已返回批次丢失。100 条文本拆 4 批时，第 2 批网络抖动会让全部向量丢失。
- **修复**: 循环内 `try/catch`，单批失败时 `log.warn` + 为该批补零向量（`createZeroVectors`）继续后续批次，与"空文本返回零向量"的容错语义一致，保证整体部分可用。

### P1-3 [docs] OpenAPI trace 路径参数名不一致

- **文件**: `docs/api/library-api.yaml:2059` vs `KnowledgeGraphController.java:54`
- **问题**: OpenAPI 文档 `/api/v1/kg/book/{id}/trace`（参数名 `id`），实际 Controller `@GetMapping("/kg/book/{bookId}/trace")`（参数名 `bookId`）。前后端契约不一致。
- **修复**: OpenAPI 路径与 path 参数统一改为 `{bookId}`，与 getBookGraph/keypath/rebuild 端点一致。

### P1-4 [docs] OpenAPI keypath 查询参数名不一致

- **文件**: `docs/api/library-api.yaml:2211` vs `KnowledgeGraphController.java:70`
- **问题**: OpenAPI 关键路径端点查询参数 `targetId`，实际 Controller `@RequestParam Long targetBookId`。前端按 OpenAPI 传 `targetId` 会被后端忽略。
- **修复**: OpenAPI 参数名改为 `targetBookId`。

### P1-5 [docs] 架构文档 §2.3 用户管理权限注释与 Controller 不一致

- **文件**: `docs/系统架构设计文档.md:150` vs `AdminUserController.java:49,67`
- **问题**: 架构文档注明 `GET /admin/users`、`PUT /admin/users/{id}/status` → "Admin 专有"，实际 Controller 标注 `@RequireRole({LIBRARIAN, ADMIN})`，即 Librarian 亦可访问。
- **修复**: 修正架构文档注释为"Librarian 及以上（对齐 `AdminUserController` 的 `@RequireRole({LIBRARIAN, ADMIN})`）"。代码与类注释一致且符合角色总表"图书管理员读者管理"职责，故以代码为准修正文档。

### P1-6 [bootstrap/security] JWT 默认密钥长度不足致开发环境启动失败（回归）

- **文件**: `application.yml:96` + `JwtProperties.java:25`
- **问题**: 第一轮"JWT Secret 开发环境加固"将 `jwt.secret` 默认值由空串 `""` 改为 `dev-only-do-not-use-in-prod`（27 字节），但 `JwtProperties.@PostConstruct` 校验要求 **≥ 32 字节**（HS256），故该默认值会触发 fail-fast 抛 `IllegalStateException`——**开发环境未设 `JWT_SECRET` 环境变量时应用启动失败**。测试因不加载完整 Spring 上下文而未暴露。
- **修复**: 默认值改为 `library-system-dev-jwt-secret-replace-in-production-2026`（56 字节 ≥ 32，通过校验）。`application.yml` 与 `JwtProperties` Java 层默认值同步一致。生产环境仍通过 `JWT_SECRET` 环境变量注入强随机密钥。
