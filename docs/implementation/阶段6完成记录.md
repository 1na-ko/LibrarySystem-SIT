## 1. 完成概要

阶段 6 实现了图书推荐引擎的**多路召回 + 加权融合 + LLM 理由生成**完整链路。
三路召回并行执行（协同过滤、内容推荐、知识图谱），加权融合后精排 Top-N，
通过 LLM 生成个性化推荐理由（LLM 不可用时降级为模板）。

核心设计原则：
- **并行召回**：`CompletableFuture` 三路并行，超时 5s 使用已完成路径
- **降级优先**：LLM 不可用 → 模板理由；EmbeddingService 缺失 → Content 路静默跳过；KG 未就绪 → 返回空
- **N+1 消除**：CF 全量一次加载、图书批量 `selectBatchIds`、分类名批量 Map 回填

## 3. 关键设计决策

| 决策 | 理由 |
|------|------|
| KG 路直接空实现（非 `@ConditionalOnBean`） | Neo4jClient Bean 不存在，条件注入无意义；阶段 7 直接替换 |
| EmbeddingService 构造器注入 + `@Nullable` | 无 API Key 时 Content 路静默跳过，不阻塞其他推荐路 |
| LLM 降级静默（仅日志 Warn） | 推荐结果仍可用（有分数），理由用模板不影响用户体验 |
| CF 全量加载 `borrow_record`（一次查询） | 高校图书馆量级（万级）可接受；避免 N+1 |
| 图书批量加载 + 分类名 Map 回填 | 消除 N+1；参考 `RelatedBookServiceImpl` 模式 |
| `BookRecommendVO` 复用 | 已有 `book(BookSimpleVO) + score + reason` 三字段，完美匹配 |
| Controller 放 `library-security` | 遵循 ADR——依赖 `SecurityUtils.getCurrentUserId()` 的 Controller 统一放 security |
| `RecommendationProperties` 可配置化 | 权重/Top-K/候选池上限/超时均可通过 `application.yml` 调参 |
