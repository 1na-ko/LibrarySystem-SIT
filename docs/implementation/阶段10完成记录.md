## 2. RabbitMQ 事件总线引入（主线 A）

### 2.1 设计：领域事件 + AFTER_COMMIT 桥接 + @RabbitListener 消费

- **业务发布点零改动**：`BookAdminServiceImpl`/`BorrowServiceImpl`/`ReservationExpireBatchProcessor` 仍用 `eventPublisher.publishEvent()`，保留 `@TransactionalEventListener(AFTER_COMMIT)` 事务语义
- **EventBusBridge**（`library-core/event/EventBusBridge.java`）：监听 5 个领域事件（BookCreated/Updated/Deleted/Borrowed/ReturnedEvent），事务提交后转发至 RabbitMQ。消息体为 `Long bookId`，routing key 编码事件类型
- **消费者改造**：ESSyncListener/ReservationNotifier/KgBuildListener 从 `@Async @TransactionalEventListener` 改为 `@RabbitListener`，按 `@Header(RECEIVED_ROUTING_KEY)` 分发
- **重试统一**：移除 ESSyncListener/KgBuildListener 各自手写的 3 次重试+指数退避（DRY），改由 Spring AMQP RetryTemplate 配置化（3 次指数退避 1s/2s/4s，耗尽进死信）

### 2.2 RabbitMQ 拓扑（`library-bootstrap/config/RabbitMqConfig.java`）

- Topic Exchange `library.events` + 死信交换器 `library.events.dlx` + 死信队列 `q.library.events.dlq`
- 业务队列（均 durable + `x-dead-letter-exchange`）：
  - `q.es-sync` ← `book.*`（ESSyncListener 消费所有图书事件）
  - `q.reservation-notify` ← `book.returned`（ReservationNotifier）
  - `q.kg-build` ← `book.{created,updated,deleted}`（KgBuildListener）
- Jackson2JsonMessageConverter 序列化
- 常量集中在 `library-core/event/EventBusConstants.java`（依赖方向 core ← bootstrap/kg 正确）

### 2.3 双写一致性权衡

采用「事务提交后发 MQ（afterCommit 回调）+ MQ 持久化」，**不上 Outbox**。afterCommit 后发 MQ 的崩溃丢消息窗口极小（事务已提交、仅发 MQ 一步），配合 `EsRebuildJob` 周级全量重建兜底。Outbox（本地消息表+CDC）严格不丢但过重，记为未来演进选项。

### 2.4 文档冲突消除

架构文档 §3.1 原写"模块间通过 Spring Application Events 通信"，与技术栈表/部署架构图的 RabbitMQ 冲突。阶段 10 统一到 RabbitMQ 事件总线，删除"Spring Events 替代"措辞。

## 5. 已知问题：Docker Desktop 29 兼容（阻塞集成测试运行）

### 5.1 问题

Docker Desktop 4.29+/29.x 引入 CLI 代理架构，Testcontainers 1.21.3 通过 npipe 连接时被 CLI 代理拦截，返回**空 Docker info + BadRequestException 400**（Labels 指向 `docker_cli` pipe），而 docker CLI 正常。所有检测策略（EnvironmentAndSystemProperty/NpipeSocket）均失败。

### 5.2 解决方案

1. **开启 TCP 2375（推荐）**：Docker Desktop → Settings → General 勾选 "Expose daemon on tcp://localhost:2375 without TLS"，绕过 CLI 代理直连 engine REST：
   ```bash
   make itest-tcp   # 等价 DOCKER_HOST=tcp://localhost:2375 mvn test -Pintegration
   ```
2. 降级 Docker Desktop 到 4.28.x（无 CLI 代理架构）
