## 架构决策记录

### ADR-9.1: 管理 Controller 统一置 `library-security`
`AdminUserController` 和 `AdminStatsController` 放在 `library-security` 模块，遵循既有 Controller 落位 ADR——它们使用 `SecurityUtils.getCurrentUserId()` 获取当前操作人 ID。

### ADR-9.2: 操作日志异步写入
`OperationLogAspect` 使用 `CompletableFuture.runAsync()` 异步写入日志，失败仅 log.error 不抛异常，确保审计日志不影响主流程。

### ADR-9.3: 操作日志表无 `deleted` 列
`operation_log` 表不含 `deleted` 列，因为审计日志不可删除。`OperationLogMapper` 仅使用 `insert` 操作，不受 MyBatis-Plus 全局逻辑删除影响。

### ADR-9.4: Prometheus 端点公开
`/prometheus` 加入 SecurityConfig 公开白名单（与 `/health` 一致的策略），Prometheus Server 通过网络策略隔离访问。

## 已知限制

1. **OperationLogAspect 仅拦截 `@OperationLog` 标注的方法**——当前仅 `AdminUserController.updateStatus()` 使用了该注解，其他管理端点可按需添加
2. **EsRebuildJob 采用逐条 `save()` 而非 Bulk API**——（已于阶段 9 后回溯修正改用 `BookESRepository.bulkSave` 批量写入，本限制已消除）
3. **Prometheus Counter 埋点需在 Service 中手动 `meterRegistry.counter().increment()`**——当前未全面埋点，仅在 MetricsConfig 中预留了 Gauge
