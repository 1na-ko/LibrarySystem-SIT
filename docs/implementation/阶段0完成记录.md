## 架构原则遵循

| 原则 | 体现 |
|------|------|
| **KISS** | `Result`/`PageResult`/`PageDTO` 设计极简，单一职责，无额外抽象层 |
| **YAGNI** | 仅实现当前阶段必需的工具方法和配置，未预埋未验证的扩展点 |
| **DRY** | `ErrorCode` 集中定义，`GlobalExceptionHandler` 统一异常→HTTP 映射，各层无需重复编写异常处理逻辑 |
| **SOLID-S** | `ErrorCode`（错误定义）、`BizException`（异常载体）、`GlobalExceptionHandler`（响应转换）各自单一职责 |
| **SOLID-D** | `Result<T>` 作为接口契约的抽象，Controller 依赖此抽象而非具体响应格式 |

## 与阶段 1 的衔接

阶段 1（安全与认证）将使用本阶段产出的：
- `@NoAuth` → 标记 `/auth/**` 公开端点
- `Result<T>` → 所有认证 API 的返回格式

- `GlobalExceptionHandler` → 阶段 1 的 `AuthenticationEntryPoint` 会复用 `Result.error()` 统一格式
- `AsyncConfig` → Token 异步存储/清理
