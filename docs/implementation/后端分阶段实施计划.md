## 1. 总体规划

### 1.1 实施模块与覆盖范围

| 模块 | 涉及阶段 | 产出物 |
|------|----------|--------|
| `library-common` | 0 | 统一响应体、异常体系、公共 DTO、工具类 |
| `library-security` | 1、9 | JWT 过滤器、Spring Security 配置、RBAC 处理器 |
| `library-ai` | 5 | LLM 服务封装、Embedding 服务、HanLP NLP 工具 |
| `library-core` | 2、3、4、6 | 图书/借阅/预约/推荐全部 Controller/Service/Mapper/Entity/Event/Repository |
| `library-knowledge-graph` | 7 | Neo4j Repository、图谱构建/查询/溯源 Service、KG Controller |
| `library-acquisition` | 8 | 预测/查重/缺口分析/谈判 Service 与 Controller、ML 工具类 |
| `library-bootstrap` | 0、1、9、11 | CORS 配置、异步配置、Flyway 种子脚本、全局拦截器、Actuator |

### 1.2 依赖拓扑（决定阶段顺序）

```
library-common ─────────────────────────────────────────────────────────────► (所有阶段)
library-security ───────────────────────────────────────────────────────────► (认证后所有 API)
library-ai ─────────────────────────────────────────────────────────────────► (6/7/8)
library-core (数据层) ───────────────────────────────────────────────────────► (3/4/6)
library-core (检索) ─────────────────────────────────────────────────────────► (4)
library-core (借阅预约) ─────────────────────────────────────────────────────► (6)
library-core (推荐) ─────────────────────────────────────────────────────────► (7)
library-knowledge-graph ─────────────────────────────────────────────────────► (8 缺口分析)
library-acquisition ─────────────────────────────────────────────────────────► (—)
```

### 1.3 每阶段交付标准

每个阶段结束必须满足：
- ✅ `mvn clean compile` 无错误
- ✅ 本阶段涉及的单元测试全部通过（覆盖率 ≥ 阶段目标）
- ✅ 本阶段涉及的 API 可通过 Postman/curl 手动验证
- ✅ OpenAPI 文档（SpringDoc）随变更同步更新
- ✅ 代码通过 SonarLint 检查（无 Blocker/Critical）

## 3. 阶段 1：安全与认证

> **依赖**: 阶段 0
> **目标模块**: `library-security`、`library-bootstrap`（登录 API 暂时放在 bootstrap 或 core）

### 3.1 任务清单

| # | 任务 | 产出文件 | 说明 |
|---|------|----------|------|
| 1.1 | JWT 工具类 | `security/utils/JwtUtils.java` | 基于 JJWT 0.12.x：`generateAccessToken(userId, role, 2h)`、`generateRefreshToken(userId, 7d)`、`validateToken(token)`、`parseClaims(token)` |
| 1.2 | Token 存储服务 | `security/service/TokenService.java` | Refresh Token 存入 Redis（key=`refresh:{userId}`，value=token，TTL=7d），登录时旧 Token 覆盖、刷新时旧 Token 失效（防重放） |
| 1.3 | JWT 认证过滤器 | `security/filter/JwtAuthenticationFilter.java` | `OncePerRequestFilter`：从 Header `Authorization: Bearer <token>` 提取并校验，设置 `SecurityContextHolder`；放行 `/auth/**`、`/health`、Swagger 路径 |
| 1.4 | Spring Security 配置 | `security/config/SecurityConfig.java` | 禁用 CSRF、无状态 Session、注册 JWT Filter、配置路径权限规则（基于权限矩阵 §2.3）、BCrypt PasswordEncoder Bean |
| 1.5 | 认证控制器 | `core/controller/AuthController.java` | 4 个端点：`POST /auth/login`（返回 Token 对 + UserProfile）、`POST /auth/register`、`POST /auth/refresh`、`POST /auth/logout`（使 Refresh Token 失效） |
| 1.6 | 用户注册/登录 Service | `core/service/AuthService.java` | `register(dto)`：BCrypt 哈希密码、校验用户名唯一、默认角色 STUDENT；`login(dto)`：校验密码、生成 Token 对；`refresh(refreshToken)`：校验并轮换 |
| 1.7 | User Entity + Mapper | `core/entity/SysUser.java`、`core/mapper/SysUserMapper.java` | 对应 `sys_user` 表，MyBatis-Plus BaseMapper |
| 1.8 | RBAC 权限注解 | `security/handler/PermissionHandler.java` | 自定义 `@RequireRole(RoleEnum)` 和 `@RequirePermission(String)` 注解，配合 Spring Security `@PreAuthorize` 或 AOP 切面 |
| 1.9 | Redis 令牌桶限流器 | `security/filter/RateLimitFilter.java`（或拦截器） | Lua 脚本实现令牌桶：key=`rate:{userId}`，速率 100/min，超限返回 429 + `Retry-After` Header（对齐 API 文档限流规范） |

### 3.2 验证清单

```bash
# 1. 注册
curl -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"test001","password":"Test@123456","realName":"测试","email":"test@university.edu.cn"}'
# → 200 + user profile

# 2. 登录
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test001","password":"Test@123456"}'
# → 200 + accessToken + refreshToken

# 3. 未认证请求（期望 401）
curl http://localhost:8080/api/v1/books/search?keyword=Java
# → 401

# 4. 认证后请求（使用上面获取的 token）
curl http://localhost:8080/api/v1/books/search?keyword=Java \
  -H "Authorization: Bearer <accessToken>"
# → 200（此时无数据，但认证通过）

# 5. Token 刷新
curl -X POST http://localhost:8080/api/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"<refreshToken>"}'
# → 200 + 新 Token 对

# 6. 限流验证（快速连续请求 > 100 次）
# → 429 + X-RateLimit-* Headers
```

## 6. 阶段 4：核心业务—借阅与预约

> **依赖**: 阶段 3（图书数据就位）
> **目标模块**: `library-core`

### 6.1 任务清单

#### 6.1.1 借阅管理

| # | 任务 | 产出文件 | 说明 |
|---|------|----------|------|
| 4.1 | 借阅 Service | `core/service/BorrowService.java` | `borrow(userId, bookId)`：校验库存>0、用户未超借阅上限、无超期未还、未重复借阅；Redis 分布式锁扣库存（防超卖）；乐观锁 `version` 更新 `avail_copies`；插入 `borrow_record`；发布 `BookBorrowedEvent`（→ ES 同步 borrowCount 变化） |
| 4.2 | 归还 Service | 同上 | `returnBook(borrowId)`：校验借阅状态、计算超期天数与罚款金额（超期 = `due_date` 前未归还，日罚款 0.5 元）、更新 `borrow_record.status=RETURNED`、恢复 `avail_copies`、发布 `BookReturnedEvent`（→ 触发预约通知） |
| 4.3 | 续借 Service | 同上 | `renew(borrowId)`：校验 `renew_count < 1`、未超期、图书未被预约、due_date 延长 30 天、renew_count+1、status=RENEWED |
| 4.4 | 借阅 Controller | `core/controller/BorrowController.java` | `POST /borrows`（借书）、`PUT /borrows/{id}/return`（归还）、`PUT /borrows/{id}/renew`（续借）、`GET /borrows`（我的借阅，按 status 筛选）、`GET /borrows/{id}`（详情）、`GET /borrows/overdue`（超期，管理员） |
| 4.5 | 超期定时检查 | `core/schedule/OverdueCheckJob.java` | `@Scheduled(cron="0 0 3 * * ?")` 每天凌晨 3 点：扫描 `due_date < NOW()` 且 status IN (BORROWED, RENEWED) 的记录 → status=OVERDUE → 插入 `fine_record` |

#### 6.1.2 预约管理

| # | 任务 | 产出文件 | 说明 |
|---|------|----------|------|
| 4.6 | 预约 Service | `core/service/ReservationService.java` | `reserve(userId, bookId)`：校验库存=0（否则提示直接借阅）、未重复预约、Redis ZSET `reservation:queue:{bookId}` 按时间戳入队、持久化 reservation 记录（status=WAITING） |
| 4.7 | 取消预约 Service | 同上 | `cancel(reservationId)`：校验本人操作、status→CANCELLED、从 ZSET 移除 |
| 4.8 | 预约通知监听器 | `core/event/ReservationNotifier.java` | `@Async @EventListener` 监听 `BookReturnedEvent` → 从 Redis ZSET 弹出首位 → status→NOTIFIED → 发送通知（站内信/邮件占位，初期 log 输出）→ 设置 48h 超时（Redis key=`reservation:expire:{id}` TTL=48h，过期后自动 EXPIRED 并通知下一位） |
| 4.9 | 预约 Controller | `core/controller/ReservationController.java` | `POST /reservations`（预约）、`DELETE /reservations/{id}`（取消）、`GET /reservations`（我的预约，按 status 筛选）、`GET /reservations/{id}/queue-position`（排队位置） |
