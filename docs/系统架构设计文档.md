## 1. 项目概述

### 1.1 项目背景与愿景

本项目面向高校图书馆数字化转型场景，构建一套 **"核心借阅管理 → 学科知识图谱 → 智能采编决策"** 三层递进的智慧图书馆系统。三个版本逐层叠加能力，最终形成覆盖 **读者服务、知识发现、资源建设** 全链路的智能化平台。

```
┌─────────────────────────────────────────────────────────────────┐
│                      提高版：智能采编系统                          │
│           采购需求预测 + 查重/查缺自动化 + 电子资源智能谈判          │
│           ┌───────────────────────────────────────────┐          │
│           │           进阶版：学科知识图谱               │          │
│           │   主题关联网络 + 文献溯源路径 + 学科热点分析   │          │
│           │  ┌─────────────────────────────────────┐  │          │
│           │  │        基础版：核心借阅管理             │  │          │
│           │  │  检索 借阅 归还 续借 预约 历史 推荐     │  │          │
│           │  └─────────────────────────────────────┘  │          │
│           └───────────────────────────────────────────┘          │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 用户角色与端

| 角色 | 访问端 | 核心职责 |
|------|--------|----------|
| **读者 (READER)** | Web / 小程序 | 检索图书、申请借阅、归还、续借、预约、查看历史、获取推荐、浏览知识图谱 |
| **馆员 (LIBRARIAN)** | Web 管理后台 | 审批借阅/续借、处理归还、图书编目、馆藏管理、超期罚款、数据报表 |
| **采购管理员 (ACQUISITION)** | Web 管理后台 | 采购需求分析、供应商管理、查重查缺、订单管理、电子资源谈判 |
| **系统管理员 (ADMIN)** | Web 管理后台 | 用户管理、角色权限、系统配置、日志审计、字典维护 |

### 1.3 设计原则

| 原则 | 本系统应用 |
|------|-----------|
| **SOLID** | 每个 Service 单一职责；面向接口编程；AI 客户端通过接口抽象支持多种 LLM |
| **KISS** | 优先 Spring Boot 自动配置；DTO/VO/Entity 按需定义不过度抽象 |
| **DRY** | common 模块统一异常/响应/工具；BaseController 抽取通用 CRUD |
| **YAGNI** | 基础版不引入 Neo4j/ES；通过 feature flag 控制版本功能开关 |
| **高内聚低耦合** | 模块间 RESTful API 通信；AI 服务作为独立 infrastructure 层 |

### 3.2 AI 服务层架构（OpenAI 兼容协议）

本系统 **不绑定特定模型**，通过 OpenAI 兼容协议接入，默认使用 DeepSeek，可无缝切换至任何兼容服务（Qwen、GLM、Moonshot 等）。

```
┌────────────────────────────────────────────────────────────────────┐
│                     AI Infrastructure Layer                         │
│                                                                     │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │                   AIClient (Interface)                        │  │
│  │  + chatCompletion(ChatRequest): ChatResponse                 │  │
│  │  + chatCompletionStream(ChatRequest): Flux<ChatChunk>        │  │
│  │  + embedding(EmbeddingRequest): EmbeddingResponse            │  │
│  └──────────────────────────┬───────────────────────────────────┘  │
│                             │  implements                           │
│  ┌──────────────────────────┴───────────────────────────────────┐  │
│  │          OpenAICompatibleClient (实现)                         │  │
│  │  • baseUrl:  配置化（默认 https://api.deepseek.com/v1）       │  │
│  │  • apiKey:   环境变量注入 ${DEEPSEEK_API_KEY}                 │  │
│  │  • model:    配置化（deepseek-chat / deepseek-reasoner）      │  │
│  │  • 请求格式: 完全遵循 OpenAI Chat Completions API              │  │
│  │  • HTTP:     Spring WebClient + 连接池                        │  │
│  │  • 重试:     指数退避 (max 3 次)                              │  │
│  │  • 降级:     超时/失败 → 返回缓存结果或默认响应                 │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │                    AI Service Facade                           │  │
│  │  • AiRecommendService    — 智能推荐（解释推荐理由）            │  │
│  │  • AiExtractService      — 实体/关系抽取（图谱构建）           │  │
│  │  • AiSearchService       — 自然语言语义搜索                    │  │
│  │  • AiChatService         — AI 对话助手                         │  │
│  │  • AiAcquisitionService  — 采购预测/谈判分析                   │  │
│  │  • AiDedupService        — 智能查重（语义相似度）               │  │
│  └──────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────┘
```

### 4.3 AI 模型配置架构

```yaml
# application.yml — AI 配置
library:
  ai:
    provider: deepseek              # deepseek / openai / qwen / glm / custom
    base-url: https://api.deepseek.com/v1
    api-key: ${DEEPSEEK_API_KEY}    # 环境变量注入，禁止硬编码
    models:
      chat: deepseek-chat           # 通用对话模型
      reasoner: deepseek-reasoner   # 推理模型（复杂分析场景）
    parameters:
      default-temperature: 0.7
      default-max-tokens: 2048
      timeout: 60s
    retry:
      max-attempts: 3
      backoff-multiplier: 2.0
    fallback:
      cache-ttl: 3600               # 降级缓存 1 小时
    rate-limit:
      max-requests-per-minute: 60   # API 调用频率控制
```

```java
            .uri("/chat/completions")
            .bodyValue(request)
            .retrieve()
            .bodyToMono(ChatResponse.class)
            .timeout(properties.getTimeout())
            .retryWhen(Retry.backoff(
                properties.getRetry().getMaxAttempts(),
                Duration.ofSeconds(1)))
            .block();

            .uri("/embeddings")
            .bodyValue(request)
            .retrieve()
            .bodyToMono(EmbeddingResponse.class)
```

#### 5.3.2 文献溯源查询

**Cypher 查询 — 某主题文献演进路径：**

```cypher
// 从一本经典著作出发，追溯引用链
MATCH path = (start:Book {isbn: $isbn})-[:CITES*1..4]->(end:Book)
OPTIONAL MATCH (end)-[:BELONGS_TO]->(cat:Category)
RETURN path, cat.name AS category
ORDER BY length(path)

// 作者合作网络
MATCH (a:Author {name: $authorName})-[:WRITTEN_BY]-(b:Book)-[:WRITTEN_BY]-(co:Author)
WHERE a <> co
RETURN co.name AS coAuthor, COUNT(b) AS collaborationCount
ORDER BY collaborationCount DESC

// 学科热点聚类
MATCH (kw:Keyword)<-[:HAS_KEYWORD]-(b:Book)<-[:CONTAINS]-(br:BorrowRecord)
WHERE br.borrowDate > $recentDate
WITH kw, COUNT(br) AS borrowCount
RETURN kw.word, borrowCount
ORDER BY borrowCount DESC
LIMIT 20
```

### 8.2 SSE 流式客户端设计

```typescript
// api/sse-client.ts
// 基于 Fetch API 的 SSE 流式读取，兼容 OpenAI 格式

export async function* chatStream(
  messages: ChatMessage[],
  signal?: AbortSignal
): AsyncGenerator<ChatChunk> {
  const response = await fetch('/api/v1/ai/chat/stream', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${getToken()}`
    },
    body: JSON.stringify({ messages, stream: true }),
    signal
  });

  if (!response.ok) throw new Error(`HTTP ${response.status}`);

  const reader = response.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() || '';

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = line.slice(6);
        if (data === '[DONE]') return;
        yield JSON.parse(data);
      }
    }
  }
}
```

```java
// AI 服务的单元测试 — 使用 Mock WebClient
@ExtendWith(MockitoExtension.class)
class AiRecommendServiceTest {

    @Mock
    private AIClient aiClient;

    @InjectMocks
    private AiRecommendService aiRecommendService;

    @Test
    void shouldReturnAiRecommendations() {
        // 构造 Mock ChatResponse
        ChatResponse mockResponse = new ChatResponse();
        Choice choice = new Choice();
        Message msg = new Message();
        msg.setContent("""
            [
              {"bookId": 1, "title": "深入理解Java虚拟机", "reason": "与你的借阅历史高度相关"},
              {"bookId": 2, "title": "Spring微服务实战", "reason": "拓展你的Spring技术栈"}
            ]
            """);
        choice.setMessage(msg);
        mockResponse.setChoices(List.of(choice));

        when(aiClient.chatCompletion(any(ChatRequest.class)))
            .thenReturn(mockResponse);

            .thenThrow(new TimeoutException("AI timeout"));
```
